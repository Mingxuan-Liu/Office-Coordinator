# tests/golden

The frozen reproducibility baseline for invariant **I3** ("same
`(responses, config, seed)` ⇒ byte-identical `results.json`").

```
inputs/config/      a complete, valid config directory  — FROZEN
inputs/responses.csv the matching response export       — FROZEN
results.json        the bytes those inputs must produce — regenerate deliberately
```

## The inputs are frozen literal files

They were produced once by `deskmatch.synth` and then committed as ordinary
files. They are **not** regenerated by the test suite, and nothing in the suite
writes to `inputs/`. That is the point: if the golden inputs were re-derived
from the generator, a change to `synth.py` would silently change what the golden
file is testing, and the baseline would certify nothing.

Editing anything under `inputs/` is therefore a deliberate act. The test
`TestGoldenFile::test_golden_inputs_have_not_been_edited` compares their sha256
against the hashes recorded inside `results.json` and fails if they drift.

## What the case exercises

It is deliberately not a happy path. Beyond a plain feasible solve it contains
desk keepers (people and desks removed from the pool), a desk marked
`"available": false`, choices dropped because they name a desk that has left the
pool, roster/submission conflicts on `year` and `candidacy`, re-submissions
(including a duplicated timestamp, so the file-position tie-break is live), the
whole yes/no token vocabulary in `keeps_desk`, an extra roster column, and two
zones with a cohort eligibility rule. `TestGoldenFile::test_the_golden_case_is_worth_having`
asserts each of those is still present, because a golden file over a trivial
instance is a golden file that certifies nothing.

## Regenerating `results.json`

Only when you have decided the output *should* change:

```bash
DESKMATCH_UPDATE_GOLDEN=1 PYTHONPATH=solver python3 -m pytest \
    tests/test_determinism.py::TestGoldenFile::test_golden_results_json
```

That run rewrites the file and then **fails on purpose**, so a regeneration can
never be mistaken for a passing test. Read `git diff tests/golden/results.json`,
confirm every changed line is intended, re-run without the variable, and commit
the golden file in the same commit as the change that moved it.

## Why three version fields are pinned

`python`, `numpy` and `scipy` are replaced with `PINNED-FOR-GOLDEN-FILE` before
the document is written (`tests/pipeline.py`). SPEC §7.1 puts those versions
inside the canonical hash on purpose — correct for an audit trail, intolerable
for a committed baseline, because `pip install -U numpy` would expire it with no
change to the answer. `deskmatch_version` is **not** pinned: it lives in a
tracked file, so moving it is a repository change and should require a
deliberate regeneration.

`TestGoldenFile::test_pinning_conceals_nothing_else` compares a pinned run
against a live one field by field and fails if anything outside that pinned set
differs, so the pinning cannot hide a regression.
